# <项目名> - <一句话定位>

## 原则
1. 唯一出处：同一事实/标准只在一处定义（ssot/），其余地方只引用。
2. 先改规范再改实现：正确性问题的修复顺序。
3. AI 对 ssot/ 全层只读：SSOT 由程序员维护；AI 可起草，人采纳了才算数。
4. 够用是铁律：三层八文件，不增不减。

## 角色
- 负责人：批准本文件头部（治理规则）的修改。
- 程序员：SSOT 的维护者；各层改动按各自门槛执行。
- AI：负责实现；开发 session 中对本目录全层只读，严禁修改。

## 改动门槛
- 本文件头部：须负责人批准。
- L0 需求层：变更必录——先追加 change-log.md，再更新波及文件。
- L1 事实层：修改落地前须过第二双眼睛。
- L2 流程层：程序员日常维护。
- 变更流程（顺序锁死）：需求变更 → 录入 change-log → 更新波及文件 → 实现跟进。

## 渐进披露（读取纪律）
- 入口最小化：AI 会话只从本文件进入 ssot/；工具入口文件（CLAUDE.md/AGENTS.md 等）只指路到这里，不复制内容。
- 索引先行：每个层文件头部有 `## 索引`（一行一条目：编号|标题|关键词）；索引只引用、不定义。
- 全文阈值：层文件 ≤ 300 行可全文读；超过必须 grep 编号/关键词定位后按行号取段，禁止全文读取。
- 拆分阈值：层文件超过 400 行时按域拆分为 `<名>-<域>.md`，原文件退化为纯索引（每域一行）；八个入口不变。
- 任务简报：/gsdd-load 产出的简报 ≤ 2000 token，只含相关验收项全文、术语口径、波及剧本步骤、禁止事项，不落盘。

## 验收三层单向引用
acceptance.md（验什么）→ testcase.md（怎么验）→ tests/（怎么自动跑）。
下层只引用编号，不许反向定义；编号（R/A）是引用链的通货，编号不复用，作废只标注不删除。
AI 只执行验收并产出证据（存 evidence/，不进 ssot/），无权自造或改写验收项。
