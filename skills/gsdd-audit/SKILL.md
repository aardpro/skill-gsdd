# GSDD 体检

只读检查，输出违规清单（按严重度排序）+ 修复建议；修复走 `/gsdd-change` 或由人执行。没有 ssot/ → 提示 `/gsdd-init`。

## 检查项

1. **结构**：入口文件齐备（README + 文件清单所列入口，见 `ssot/README.md`）；拆分文件（`<名>-<域>.md`）必须被原入口文件索引登记，**孤儿文件（不在任何入口索引里）报警**；README 头部含治理规则与渐进披露阈值（全文/拆分）。
2. **编号通货**：
   - acceptance 的 A 号无重号；testcase 引用的 A 号都存在；tests/ 源码里 grep 到的 A 号都存在。
   - requirements 的 R 号同理。
   - schema 的 S 号无重号、支撑的 R 号存在（无 S 号登记时跳过此项，只提示补登记）。
   - stack/decisions 引用的 D 号存在；decisions 的 D 号无重号、被「取代」标注的旧号仍有指向。
   - 被引用的编号若已标注作废 → 报警（引用链悬空）。
3. **索引一致性**：每文件 `## 索引` 条目与正文条目一一对应——漏索引、死索引都算违规。
4. **唯一出处（启发式）**：术语在 design/schema/testcase 里被「定义式」复述的候选点；schema 字段映射不到术语的候选点；同一组件在 stack 与 design 里双写版本/约束的候选点。启发式结果只提示人工复核，不定罪。
5. **只追加约束**：在 git 仓库内时，检查 change-log.md 历史是否只追加（旧内容须为新内容的前缀；重排/删除/改写即违规）。
6. **单向门完备性**：decisions.md 里标记单向门的条目，替代方案、回退成本、批准人三项缺任一 → 违规；schema/stack 里标注单向门的条目若无对应 D 号 → 提示补决策记录。
7. **迁移对账（启发式，只读）**：schema.md 条目登记的迁移编号与代码库 migration 目录（按常见命名探测）对账——落后、对不上只提示人工复核，不定罪；schema 引用的字段/表在 migration 中无迹可循的候选点提示复核。
8. **规模预警**：单层文件超过拆分阈值（README 头部声明，默认 400 行）→ 给出按域拆分建议（`<名>-<域>.md`，原文件退化为纯索引）；超过全文阈值（默认 300 行）→ 提醒读取纪律已生效。
