# GSDD 体检

只读检查，输出违规清单（按严重度排序）+ 修复建议；修复走 `/gsdd-change` 或由人执行。没有 ssot/ → 提示 `/gsdd-init`。

## 检查项

1. **结构**：ssot/ 下恰好八文件 + README，无多余文件；README 头部含治理规则与渐进披露阈值（全文/拆分）。
2. **编号通货**：
   - acceptance 的 A 号无重号；testcase 引用的 A 号都存在；tests/ 源码里 grep 到的 A 号都存在。
   - requirements 的 R 号同理。
   - 被引用的编号若已标注作废 → 报警（引用链悬空）。
3. **索引一致性**：每文件 `## 索引` 条目与正文条目一一对应——漏索引、死索引都算违规。
4. **唯一出处（启发式）**：术语在 design/testcase 里被「定义式」复述的候选点；design 字段映射不到术语的候选点。启发式结果只提示人工复核，不定罪。
5. **只追加约束**：在 git 仓库内时，检查 change-log.md 历史是否只追加（旧内容须为新内容的前缀；重排/删除/改写即违规）。
6. **规模预警**：单层文件超过拆分阈值（README 头部声明，默认 400 行）→ 给出按域拆分建议（`<名>-<域>.md`，原文件退化为纯索引）；超过全文阈值（默认 300 行）→ 提醒读取纪律已生效。
